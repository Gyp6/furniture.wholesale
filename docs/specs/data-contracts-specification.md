# 📑 Специфікація форматів обміну даними (Data Contracts)

Цей документ визначає технічні контракти для обміну JSON-даними, структуру моделей (DTO) та уніфікований формат обробки помилок.

---

## 1. Опис моделей даних (DTO Specification)

Для кожної сутності ми розділяємо **Request DTO** (дані від клієнта) та **Response DTO** (безпечні дані від сервера), щоб уникнути витоку технічної інформації (паролі, хеші, системні ID).

### 🏷️ Сценарій 1: Створення картки товару (Catalog Module)
**Кейс:** Адмін додає новий диван у каталог.

* **Request (POST `/api/v1/catalog`):**
```json
{
  "sku": "FURN-SOFA-99",
  "name": "Диван 'Президент'",
  "categoryId": "uuid-cat-123",
  "wholesalePrice": 8500.00,
  "stockQuantity": 25,
  "specifications": {
    "material": "Leather",
    "color": "Black"
  }
}
```

* **Response (201 Created):**
```json
{
  "id": "uuid-prod-999",
  "sku": "FURN-SOFA-99",
  "name": "Диван 'Президент'",
  "wholesalePrice": 8500.00,
  "stockQuantity": 25,
  "status": "ACTIVE",
  "createdAt": "2026-04-11T12:00:00Z"
}
```

### 📦 Сценарій 2: Створення оптового замовлення (Billing Module)
**Кейс:** Покупець замовляє партію стільців.

* **Request (POST `/api/v1/orders`):**
```json
{
  "items": [
    { "productId": "uuid-prod-1", "quantity": 10 },
    { "productId": "uuid-prod-2", "quantity": 5 }
  ],
  "deliveryAddress": "м. Чернівці, вул. Головна, 100"
}
```

* **Response (201 Created):**
```json
{
  "orderId": "ORD-2026-001",
  "status": "PENDING",
  "totalAmount": 125000.50,
  "estimatedDelivery": "2026-04-15",
  "createdAt": "2026-04-11T12:05:00Z"
}
```

## 2. Глобальна схема помилок (Global Error Schema)

Сервер NestJS використовує уніфікований формат для всіх типів помилок. Це гарантує, що фронтенд (Next.js) завжди зможе коректно відобразити повідомлення користувачу.

**Приклад об’єкта помилки (409 Conflict):**
```json
{
  "timestamp": "2026-04-11T12:10:00Z",
  "errorCode": "INSUFFICIENT_STOCK",
  "message": "Неможливо створити замовлення: недостатньо товару 'Стілець Офісний' на складі",
  "path": "/api/v1/orders",
  "details": [
    {
      "field": "quantity",
      "error": "Замовлено: 10, в наявності: 3"
    }
  ]
}
```

## 3. Мапа статус-кодів (Status Code Map)

Ми використовуємо стандартні HTTP-коди для класифікації відповідей сервера. Це дозволяє фронтенду (Next.js) передбачувано обробляти результати запитів.

| Код | Назва | Кейс використання у проекті Furniture.Wholesale |
| :--- | :--- | :--- |
| **200** | OK | Успішне завантаження списку меблів, отримання профілю користувача або зміна пароля. |
| **201** | Created | Успішне створення нової картки товару в каталозі або оформлення нового замовлення. |
| **204** | No Content | Успішне видалення товару з каталогу або очищення кошика (відповідь без тіла). |
| **400** | Bad Request | Помилка валідації: передано від'ємну ціну, невалідний UUID або пусте обов'язкове поле. |
| **401** | Unauthorized | Користувач не авторизований (відсутня або недійсна сесія Better Auth). |
| **403** | Forbidden | Клієнт намагається зайти в адмін-панель або змінити ціну товару, не маючи прав адміна. |
| **404** | Not Found | Спроба отримати деталі замовлення або товару за ID, якого не існує в базі PostgreSQL. |
| **409** | Conflict | Порушення бізнес-логіки: спроба замовити 100 стільців, коли на складі залишилося лише 20. |
| **500** | Internal Error | Несподівана помилка сервера: збій підключення до бази даних або помилка в коді NestJS. |
